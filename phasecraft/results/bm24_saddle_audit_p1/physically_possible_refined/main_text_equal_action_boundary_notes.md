# Main-Text Equal-Action Figure Notes

This note explains how `main_text_equal_action_boundary.pdf/png` was made and what information it uses.

## Purpose

The simplified main-text figure is a presentation figure, not a new numerical audit.  It distills the detailed two-panel diagnostic into one beta-Gamma plot:

- resolved equal-action boundary points;
- one partial beta=0.60 candidate;
- all phase-alignment candidates as supporting diagnostics.

The detailed diagnostic figure remains:

- `separated_crossover_and_pl_conditions.pdf`
- `separated_crossover_and_pl_conditions.png`

## Script

The figure is generated by:

```bash
PYTHONPATH=/Users/b/Quandela python experiments/bm24_saddle_audit_p1/main_text_equal_action_figure.py
```

The script writes:

- `main_text_equal_action_boundary.pdf`
- `main_text_equal_action_boundary.png`
- `main_text_equal_action_boundary_caption.txt`

## Data Used

### Resolved equal-action boundary

The filled purple circles come from:

```text
equal_real_action_refined_brackets.json
```

Only rows with `status: ok` are plotted as resolved boundary points.  These are equal-real-action brackets with Krawczyk-certified endpoint saddles.  The scalar Gamma root itself is represented by the bracket midpoint; it is not claimed to be a rigorous interval proof in Gamma.

The plotted resolved betas are:

```text
0.400000
0.450000
0.500000
0.5433996421
0.575000
0.625000
0.650000
```

The solid purple guide line connects only neighboring resolved points on the same side of beta=0.60.  It is a visual guide, not a certified two-dimensional continuation.

### beta=0.60 partial candidate

The open purple diamond at beta=0.60 comes from:

```text
beta060_equal_action_roots.json
```

The beta=0.60 branch-resolution audit found two partial sign-change brackets near Gamma about `1.859`:

```text
branch_left:  Gamma in [1.857500, 1.860000]
branch_right: Gamma in [1.858750, 1.859375]
```

These overlap on:

```text
[1.858750, 1.859375]
```

The plotted open diamond is placed at the midpoint of that overlap:

```text
Gamma = 1.8590625
```

It is open, not filled, because the beta=0.60 candidate has weaker numerical status than the resolved neighboring points.  The same competitor branch was not certified cleanly through the beta=0.60 slice.

The dotted purple guide segments from beta=0.575 to beta=0.60 and from beta=0.60 to beta=0.625 are deliberately visual only.  They communicate that the partial point lies on the surrounding trend, while preserving the weaker branch-resolution status.

## Was PL Used?

Yes, but only for the gray supporting diagnostics.

The gray squares are phase-alignment candidates derived from the Picard-Lefschetz homotopy tracker outputs:

```text
pl_homotopy_all_slices/pl_homotopy_all_slices.json
```

For each beta slice, the script reads tracked competitor rows, unwraps the raw phase difference blockwise, and plots zeros of the phase-alignment condition.

These PL phase points are necessary-condition candidates only.  They are not used to define the purple equal-action boundary, and no thimble intersection numbers were computed.

## What Is Not Shown

The simplified figure intentionally removes:

- the residual heatmap;
- the colorbar;
- the beta=0.60 inset;
- duplicate black equal-action points;
- separate `branch_left` and `branch_right` symbols;
- branch assignment details;
- finite-n residual diagnostics.

Those details are preserved in the appendix-style diagnostic outputs and JSON files.

## Interpretation

The main message is:

> The resolved equal-action boundary is smooth on the clean slices, and beta=0.60 lies near the same trend, but beta=0.60 remains a partial branch-resolved candidate rather than a certified same-branch continuation.

The PL phase-alignment candidates provide supporting context only.  They should not be presented as proof of thimble intersection changes.
